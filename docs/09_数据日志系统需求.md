# 数据日志系统需求文档

> 装置终端新增 Tab：数据日志。宠物和用户共享同一个日志基础设施，通过分区隔离。

---

## 一、系统定位

- **功能定位**：轻量笔记/日志系统，挂载在装置终端面板中作为新 Tab
- **与待办的区别**：笔记没有"完成"状态，不触发提醒，纯粹是记录
- **双分区设计**：宠物和用户各自独立的日志区域，互不干扰

### 命名

| 层级 | 名称 | 说明 |
|------|------|------|
| Tab 标题 | 数据日志 | 装置终端第 5 个 Tab |
| 宠物分区 | 机体记录 | 宠物自动生成的观察日志 (后期接入行为采集) |
| 用户分区 | 操作员备忘 | 用户手动创建的笔记 |

---

## 二、数据模型

### 单条日志结构

```gdscript
{
    "id": "1715760000_12345",       # unix时间戳_随机数
    "title": "标题",                # 日志标题
    "content": "正文内容",           # 纯文本 (后期 Markdown)
    "tags": ["idea"],               # 用户自定义标签
    "source": "user",               # "user" = 操作员备忘 / "pet" = 机体记录
    "created": "2025-05-15 08:30",  # 创建时间
    "updated": "2025-05-15 09:00",  # 最后修改时间
}
```

### 存储方式

通过 `SettingsManager` 持久化到 `user://settings.cfg` 的 `[datalogs]` 节点：

```ini
[datalogs]
entries=[{"id":"...","title":"...","content":"...","tags":[],"source":"user","created":"...","updated":"..."}]
```

### 读写接口

```gdscript
# 读取全部日志
var logs: Array = SettingsManager.get_datalogs()

# 保存 (整个数组替换)
SettingsManager.save_datalogs(logs)
```

```
│   ├── HBoxContainer (分区切换)
│   │   ├── Button "机体记录"      ← 宠物日志分区
│   │   └── Button "操作员备忘"    ← 用户笔记分区
│   │
│   ├── HBoxContainer (工具栏)
│   │   ├── LineEdit (搜索/筛选)
│   │   └── Button "+ 新建"       ← 仅用户分区可新建
│   │
│   └── ScrollContainer
│       └── VBoxContainer (日志卡片列表)
│           ├── LogCard 1
│           ├── LogCard 2
│           └── ...
│
├── VSeparator
│
└── VBoxContainer (右栏: 日志详情/编辑)
    ├── LineEdit (标题编辑)
    ├── HBoxContainer (标签区)
    │   ├── Label 标签1
    │   ├── Label 标签2
    │   └── Button "+ 标签"
    ├── HSeparator
    ├── TextEdit (正文编辑)
    └── HBoxContainer (底部)
        ├── Label "创建于 2025-05-15"
        ├── Spacer
        └── Button "删除"
```

### 分区行为

| 操作 | 机体记录 (pet) | 操作员备忘 (user) |
|------|--------------|-----------------|
| 查看 | 可以 | 可以 |
| 新建 | 仅系统写入 (后期行为采集自动生成) | 用户手动创建 |
| 编辑 | 不可编辑正文 | 可以编辑 |
| 删除 | 可以删除 (用户有最高权限) | 可以删除 |
| 标签管理 | 系统自动标签, 用户可追加 | 用户自由管理 |

### 日志卡片设计

```
┌─────────────────────────────┐
│ [标签1] [标签2]    14:30    │  ← 标签 + 时间
│ 标题文字                    │  ← 标题 (单行截断)
│ 正文预览第一行...            │  ← 内容预览 (单行, 灰色)
└─────────────────────────────┘
```

## 四、交互细节

### 新建日志
1. 点击 "+ 新建" 按钮
2. 列表顶部插入一条空白日志
3. 右栏标题输入框自动聚焦
4. 防抖自动保存 (与待办系统一致, 0.6s)

### 编辑日志
- 选中卡片 → 右栏加载内容
- 标题/正文修改后防抖自动保存
- 底部显示 "已保存" 徽章 (复用待办系统的模式)

### 删除日志
- 点击删除按钮 → 直接删除 (日志不是待办, 不需要确认)
- 宠物日志也可以删, 用户拥有完整权限

### 搜索/筛选
- 搜索框实时过滤 (标题 + 内容 + 标签模糊匹配)
- 后期可加标签筛选下拉

### 标签系统
- 标签用于分类, 纯文本字符串
- 新建标签: 输入框 + 回车确认
- 删除标签: 点击标签上的 x
- 宠物日志的系统标签带特殊样式 (比如前缀 `sys:`)

## 五、与现有系统的关系

### 与待办系统
- **完全独立**。日志没有 `done` 状态, 没有提醒, 没有进度条
- 共享 `SettingsManager` 持久化层, 但用不同的存储节点
- 后期可考虑 "从日志创建待办" 的单向转换 (非必须)

### 与观察日志系统 (09 旧文档)
- 本系统覆盖了旧 09 文档的"终端日志显示层"部分
- 旧文档中"行为数据采集"和"日志生成"是后续的数据源, 生成的内容写入本系统的 `source: "pet"` 分区
- Markdown 渲染能力接入也是后续工作

## 六、技术实现

| 文件 | 职责 |

| `ui/profile/profile_tab_datalog.gd` | Tab 4: 数据日志模块 (extends HBoxContainer) |

- 复用 `ProfileStyles` 共享样式工厂
- 分区切换按钮复用已有的 Tab 样式逻辑
- 日志卡片参考游戏战绩 Tab 的深空结晶风格
