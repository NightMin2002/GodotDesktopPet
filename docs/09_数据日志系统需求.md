# 数据日志系统需求文档

> 装置终端新增 Tab：数据日志。宠物和用户共享同一个日志基础设施，通过分区隔离。

---

## 一、系统定位

- **功能定位**：轻量笔记/日志系统，挂载在装置终端面板中作为新 Tab
- **与待办的区别**：笔记没有"完成"状态，不触发提醒，纯粹是记录
- **双分区设计**：宠物和用户各自独立的日志区域，互不干扰

### 命名

| 层级 | 名称 | 说明 |
|------|------|------|
| Tab 标题 | 数据日志 | 装置终端第 4 个 Tab (索引 3) |
| 宠物分区 | 机体记录 | 宠物自动生成的观察日志 (后期接入行为采集) |
| 用户分区 | 操作员备忘 | 用户手动创建的笔记 |

## 二、数据模型

### 单条日志结构

```gdscript
{
    "id": "1715760000_12345",       # unix时间戳_随机数
    "title": "标题",                # 日志标题
    "content": "正文内容",           # 纯文本 (后期 Markdown)
    "tags": ["idea"],               # 用户自定义标签
    "source": "user",               # "user" = 操作员备忘 / "pet" = 机体记录
    "created": "2026-05-15 08:30",  # 创建时间
    "updated": "2026-05-15 09:00",  # 最后修改时间
}
```

### 存储方式

通过 `SettingsManager` 持久化到 `user://settings.cfg` 的 `[datalogs]` 节点：

```ini
[datalogs]
entries=[{"id":"...","title":"...","content":"...","tags":[],"source":"user","created":"...","updated":"..."}]
```

### 读写接口

```gdscript
# 读取全部日志
var entries: Array = SettingsManager.get_datalogs()

# 保存 (整个数组替换)
SettingsManager.save_datalogs(entries)
```

### 分区行为

| 操作 | 机体记录 (pet) | 操作员备忘 (user) |
|------|--------------|--------------------|
| 查看 | 可以 | 可以 |
| 新建 | 仅系统写入 (后期行为采集自动生成) | 用户手动创建 |
| 编辑标题 | 可以 | 可以 |
| 编辑正文 | 不可编辑 | 可以编辑 |
| 删除 | 可以删除 (用户有最高权限) | 可以删除 |
| 标签管理 | 系统自动标签, 用户可追加 | 用户自由管理 |

### 日志卡片设计

```
┌─[左侧高亮边]────────────────────────┐
│ [标签胶囊] [标签胶囊]  2026-05-15 09:00 │  ← 胶囊徽章 + 完整时间戳
│ 标题文字                               │  ← 标题 (单行截断, 空标题显示灰色"无标题")
│ 正文预览第一行...                       │  ← 内容预览 (60字截断)
└──────────────────────────────────────┘
```

- 选中态: 左侧边框加粗 (3px) + 高亮 + 背景加深
- hover: 背景亮度微升 + 边框变色
- 标签最多显示 3 个

### 标签胶囊徽章

```
┌──────────┐
│  标签文本 x │  ← 圆角 8px, 带背景色 + 细边框
└──────────┘
```

- 卡片中的徽章: 只读, 无 x 按钮
- 详情面板中的徽章: 带 x 删除按钮

## 四、交互细节

### 新建日志
1. 点击 "+ 新建" 按钮
2. 列表顶部插入一条日志, 默认标题: "备忘 MM-DD HH:MM"
3. 右栏标题输入框自动聚焦并全选, 方便直接覆盖
4. 新卡片淡入动画 (0.25s)
5. 防抖自动保存 (0.6s)

### 编辑日志
- 选中卡片 → 右栏加载内容
- 标题/正文修改后防抖自动保存
- 底部显示 "已保存" 徽章 (1.5s 后恢复为创建时间)

### 删除日志
- 点击 "删除记录" → 进入确认态 ("确认删除?" 红色高亮)
- 3 秒内再次点击 → 真正删除
- 3 秒后自动恢复为普通态
- 切换选中条目时自动重置确认态
- 宠物日志也可以删, 用户拥有完整权限

### 搜索/筛选
- 搜索框实时过滤 (0.3s 防抖)
- 匹配范围: 标题 + 内容 + 标签 (模糊匹配)
- 后期可加标签筛选下拉

### 标签系统
- 标签用于分类, 纯文本字符串
- 新建标签: 输入框 + 回车确认, 重复标签自动忽略
- 删除标签: 点击胶囊徽章上的 x
- 宠物日志的系统标签带特殊样式 (比如前缀 `sys:`)

### 空状态

| 位置 | 条件 | 显示内容 |
|------|------|---------|
| 左栏列表 | 用户分区无记录 | "暂无备忘记录\n点击 [+ 新建] 开始记录" |
| 左栏列表 | 宠物分区无记录 | "机体日志为空\n系统尚未采集到可报告的行为数据" |
| 右栏详情 | 未选中任何条目 | "<>" 图标 + "选择一条记录查看详情" |

## 五、与现有系统的关系

### 与待办系统
- **完全独立**。日志没有 `done` 状态, 没有提醒, 没有进度条
- 共享 `SettingsManager` 持久化层, 但用不同的存储节点
- 后期可考虑 "从日志创建待办" 的单向转换 (非必须)

### 与观察日志系统 (09 旧文档)
- 本系统覆盖了旧 09 文档的"终端日志显示层"部分
- 旧文档中"行为数据采集"和"日志生成"是后续的数据源, 生成的内容写入本系统的 `source: "pet"` 分区
- Markdown 渲染能力接入也是后续工作

## 六、技术实现

### 文件规划

| 文件 | 职责 |
|------|------|
| `ui/profile/profile_tab_datalog.gd` | Tab 3: 数据日志模块 (extends HBoxContainer) |
| `core/settings_manager.gd` | 新增 `get_datalogs()` / `save_datalogs()` |

### 接入装置终端

1. `pet_profile_panel.gd` 骨架的 tabs 数组添加 "数据日志"
2. Tab 索引: 游戏战绩(0) → 能力数据(1) → 定时提醒(2) → 数据日志(3) → 关于(4)
3. 模块实例化和生命周期与其他 Tab 一致

### 样式

- 复用 `ProfileStyles` 共享样式工厂
- 分区切换按钮: 等宽无间距拼接, 底部高亮指示条
- 日志卡片: 深色透光背景 + 左侧高亮边框 + hover 变色
- 标签: 圆角 8px 胶囊徽章, 带主题色背景
- 详情头部: "ENTRY //" 前缀标记
- 删除按钮: 二次点击确认机制
