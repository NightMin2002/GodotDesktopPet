# 游戏终端开发指南

> 本文档描述 `ui/game_terminal/` 模块化插件架构的开发流程。
> 旧版 `games/` 扩展包系统文档见 `06_游戏扩展系统_已冻结.md`（代码已冻结，仅供参考）。

## 架构概览

```
ui/game_terminal/
    game_terminal.gd           ← 面板骨架 (CanvasLayer)
    terminal_game_base.gd      ← 游戏基类 (TerminalGameBase)
    terminal_game_icon.gd      ← 图标基类 (TerminalGameIcon)
    theme/
        styles.gd              ← 共享样式工厂 (GameTerminalStyles)
        frame.gd               ← 边框渲染器
    games/                     ← 游戏插件目录 (自动发现，零入侵)
        ttt/                   ← 每个子目录 = 一个游戏
            game.gd            ← extends TerminalGameBase
            icon.gd            ← extends TerminalGameIcon
        minesweeper/
        2048/
        snake/
        tetris/
```

**核心原则**: 新增游戏只需在 `games/` 下创建文件夹，放入 `game.gd` + `icon.gd`，不需要修改骨架任何代码。

## 新增游戏步骤

### 1. 创建目录

```
games/my_game/
    game.gd    ← 必须
    icon.gd    ← 必须
```

### 2. game.gd 模板

```gdscript
extends TerminalGameBase

# ── 元数据 (必须覆写) ──
func get_game_id() -> String: return "my_game"
func get_game_name() -> String: return "显示名称"
func get_game_desc() -> String: return "一句话描述"
func supports_auto_play() -> bool: return false

# ── 生命周期 ──
func build() -> void:
    mouse_filter = Control.MOUSE_FILTER_STOP
    set_anchors_preset(Control.PRESET_FULL_RECT)
    # 构建游戏 UI...
    start_game()

func start_game() -> void:
    # 初始化/重开一局
    game_started.emit()

# ── HUD 数据 (可选) ──
func get_hud_data() -> Dictionary:
    return {
        "score": { "label": "分数", "value": "0", "color": GameTerminalStyles.bright() },
    }

# ── AI 自玩 (supports_auto_play=true 时需实现) ──
func auto_play_step() -> void:
    pass

# ── 结算 ──
# 游戏结束时调用: game_over.emit(0)  # 0=胜, 1=负, 2=平
# 结算覆盖层用工厂:
# var d = GameTerminalStyles.create_result_overlay("再来一局", start_game)
```

### 3. icon.gd 模板

```gdscript
extends TerminalGameIcon

func _draw() -> void:
    var w = size.x
    var h = size.y
    var a = alphas()  # [base_alpha, highlight_alpha] 基于 hover 状态

    # 用 draw_line / draw_arc / draw_rect 等绘制动态图标
    # 可用: hue(), line_color(), accent_color(), _time, _hovered
    draw_line(Vector2(w*0.2, h*0.5), Vector2(w*0.8, h*0.5), line_color(), 1.5)
```

### 4. 完成

启动游戏，骨架 `_scan_games()` 自动发现并注册到大厅。

## TerminalGameBase 接口

| 方法 | 类型 | 说明 |
|------|------|------|
| `get_game_id()` | 必须覆写 | 唯一标识 (用于战绩 key、文件夹名) |
| `get_game_name()` | 必须覆写 | 大厅显示名称 |
| `get_game_desc()` | 必须覆写 | 大厅简短描述 |
| `supports_auto_play()` | 必须覆写 | 是否支持 AI 自玩 |
| `build()` | 必须覆写 | 构建 UI 并启动首局 |
| `start_game()` | 必须覆写 | 开始/重开一局 |
| `get_hud_data()` | 可选覆写 | HUD 数据槽位 (骨架每帧轮询) |
| `get_best_score()` | 可选覆写 | 最佳分数 (骨架持久化) |
| `auto_play_step()` | 可选覆写 | AI 每步操作 (骨架 Timer 驱动) |

**信号:**
- `game_started` — 新局开始时发出
- `game_over(result: int)` — 游戏结束时发出 (0=胜, 1=负, 2=平)

## TerminalGameIcon 接口

| 成员 | 说明 |
|------|------|
| `game_id: String` | 骨架设置，可读取 |
| `_hovered: bool` | 骨架驱动的悬停状态 |
| `_time: float` | 内部时钟 (自动累加) |
| `hue() -> float` | 当前 UI 主题色相 |
| `alphas() -> Array` | `[base, highlight]` 透明度 (基于 hover) |
| `line_color() -> Color` | 主题色线条颜色 |
| `accent_color() -> Color` | 主题色强调颜色 |

子类只需覆写 `_draw()` 绘制图标，`_process` 和 `queue_redraw()` 已由基类处理。

## GameTerminalStyles 工厂

| 方法 | 返回 | 用途 |
|------|------|------|
| `accent() -> Color` | 主题强调色 | 活跃状态、按钮等 |
| `dim() -> Color` | 低亮度色 | 次要文本 |
| `bright() -> Color` | 高亮色 | 标题、重点 |
| `status_active() -> Color` | 绿色系 | 就绪/胜利状态 |
| `status_warning() -> Color` | 琥珀色 | 警告状态 |
| `separator_style() -> StyleBoxFlat` | 分隔线 | 大厅分隔线 |
| `create_result_overlay(btn_text, callback) -> Dictionary` | `{overlay, label, btn}` | 结算覆盖层 |
| `show_result_overlay(overlay, label, text, color)` | void | 显示结算覆盖层 |
| `add_tech_brackets(control, size, offset)` | void | 科技感角落包边 |
| `dim_label(text, size) -> Label` | Label | 创建低亮度标签 |

## 骨架状态机

```
CLOSED → LOBBY → PLAYING → RESULT → LOBBY
                    ↑                  |
                    └──────────────────┘ (再来一局)
```

## 大厅布局

主从布局 (Master-Detail):
- 左侧: 可滚动游戏列表，悬浮即选中
- 右侧: 预览面板 (大号图标 + 名称/描述/战绩 + 启动/委托按钮)
- 点击列表项或右侧"启动推演"按钮启动游戏

## 开发规范

### 渲染方式

终端游戏支持两种渲染:
- **Canvas `_draw()` 自绘** — 井字棋、贪吃蛇、俄罗斯方块使用
- **Godot Control 节点树** — 扫雷、2048 使用

两种方式在全息屏投影中效果一致。

### 话术系统

洗牌防重复模式:

```gdscript
const _POOL_XXX := ["台词1", "台词2", ...]
var _q_xxx: Array = []

# 从队列取一条 (空了就重填+洗牌)
func _pick(queue: Array, pool: Array) -> String:
    if queue.is_empty():
        queue.append_array(pool)
        queue.shuffle()
    return queue.pop_back()
```

### 结算覆盖层

使用 `GameTerminalStyles.create_result_overlay()` 工厂统一创建:

```gdscript
func _build_result_overlay() -> void:
    var d = GameTerminalStyles.create_result_overlay("再来一局", start_game)
    _result_overlay = d.overlay
    _result_label = d.label
    add_child(_result_overlay)

func _show_result(text: String, color: Color) -> void:
    GameTerminalStyles.show_result_overlay(_result_overlay, _result_label, text, color)
```

### 输入处理

- 通过 `gui_input` 信号连接 (Control 节点方式)
- 方向键 + WASD 建议使用 `physical_keycode` 绕过输入法

### 注意事项

1. `build()` 在节点入树后被调用 — `grab_focus()` 等操作安全
2. 布局锚点由骨架预设为 `PRESET_FULL_RECT` — `build()` 中可以重设但通常不需要
3. `game_over.emit()` 必须传入 result (0/1/2) — 骨架据此更新战绩
4. `get_hud_data()` 每帧被轮询 — 返回实时数据即可，不需要手动触发更新
