# 游戏终端系统

> 独立于装置终端的专用游戏面板。所有游戏在统一的终端框架内运行，终端自带 HUD/结算/操作栏等基础设施。

---

## 架构决策

**选型**: 完整的独立终端面板 (类似装置终端)，而非在 BaseGame 层堆叠共享 UI 组件。

**原因**: 当前游戏的表现力上限是"一个浮动的 SubViewport 窗口"。无论往里塞多少 HUD/结算屏，都无法达到装置终端级别的沉浸感 (机甲边框、转场动画、状态栏)。独立终端面板一次投入，所有游戏受益。

**两套游戏系统并存:**

| 系统 | 路径 | 定位 | 渲染方式 |
|------|------|------|----------|
| 游戏扩展包 | `games/` | 全息屏投影 + 浮动面板 + SubViewport | BaseGame + GameManager + GameChrome |
| 游戏终端 | `ui/game_terminal/` | 独立终端面板 + 内容区直接渲染 | extends Control + _draw 自绘 |

扩展包系统继续服务全息屏投影和自玩模式，游戏终端为"坐下来认真玩"的场景提供完整体验。后续按需融合。

## 视觉标识

与装置终端的视觉差异:

| 特征 | 装置终端 | 游戏终端 |
|------|---------|---------|
| 边框 | 对角切角 (左上+右下) | 对称八角 (四角全切) |
| 动效 | 电流游走 + 呼吸锁扣 | 水平扫描线 + 靶向准星 |
| 定位 | 维护/诊断 | 战术/推演 |

## 新增终端游戏流程

### 1. 创建游戏文件

在 `ui/game_terminal/` 新建 `terminal_xxx.gd`:

```gdscript
extends Control

signal game_over(result: int)  # 0=胜, 1=负, 2=平

func build() -> void:
    mouse_filter = Control.MOUSE_FILTER_STOP
    set_anchors_preset(Control.PRESET_FULL_RECT)
    # 构建 UI / 连接输入 / 初始化游戏
    start_game()

func start_game() -> void:
    # 重置棋盘状态
    game_started.emit()
    queue_redraw()

func _draw() -> void:
    # 用 Canvas API 渲染游戏画面
    pass
```

### 2. 注册到终端

在 `game_terminal.gd` 中做两处改动:

**a) 大厅加游戏卡片** — `_build_lobby_placeholder()`:
```gdscript
var card = _build_game_card("游戏名", "描述", func(): _launch_terminal_game("xxx"))
vbox.add_child(card)
```

**b) 启动加 match 分支** — `_launch_terminal_game()`:
```gdscript
"xxx":
    var g = preload("res://ui/game_terminal/terminal_xxx.gd").new()
    g.build()
    g.game_over.connect(_on_game_over)
    game = g
    game_name = "游戏名"
```

### 3. 游戏接口约定

| 必须 | 说明 |
|------|------|
| `extends Control` | 直接作为子节点挂入内容区 |
| `build()` | 初始化入口，`game_terminal.gd` 调用 |
| `signal game_over(result: int)` | 0=胜/1=负/2=平，触发终端状态切换 |
| `set_anchors_preset(FULL_RECT)` | 在 build() 中设置，填满内容区 |

| 可选 | 说明 |
|------|------|
| `start_game()` | 重开用，结算覆盖层的"再来一局"按钮调用 |
| `signal game_started` | 通知终端游戏已开始 (用于 HUD 重置) |
