# 未来规划

> 按优先级和工作量排列。每个方向标注了依赖哪些现有基础设施，方便评估可行性。

## 一、成长系统 (人设核心)

**目标**: 让宠物有"养"的感觉，而不只是一个静态工具。

架构文档里已经定义了完整的成长设定：随着使用时长和交互次数积累，傲娇露馅频率从"几乎没有"逐渐过渡到"经常翻车"。目前缺的只是实现。

### 具体内容

- **交互计数器**: 戳一戳次数、使用天数、游戏局数等，持久化到 `settings.cfg`
- **好感度等级**: 划分 3~5 个阶段 (冰山期 → 松动期 → 傲娇期)
- **话术权重调整**: 每个阶段的真心话/冷淡话比例不同，高等级解锁新话术
- **里程碑事件**: 首次启动、第 7 天、第 30 天等节点触发特殊对话

### 依赖

- `SettingsManager` 持久化 (已有)
- `poke_system.gd` 话术路由 (已有，加权重参数即可)
- `pet_chatter.gd` 碎碎念 (已有)

### 工作量: 1~2 天

## 二、窗口感知与情境反馈

**目标**: 让宠物知道用户正在做什么，并做出反应。

### 具体内容

- **前台应用识别**: `InputMonitor.cs` 已有 `GetForegroundWindow` 轮询和窗口标题统计，加一层关键词/进程名匹配规则即可
- **情境碎碎念**: 检测到浏览器标题含视频网站关键词 → "摸鱼时间已记录。"；检测到 IDE → "编译祈祷协议已就绪。"
- **专注度统计**: 基于窗口切换频率判断用户是否在频繁分心，纳入数据日志
- **久坐提醒升级**: 目前只按时间触发，结合前台应用可以更智能 (连续工作 vs 连续摸鱼区别对待)

### 依赖

- `InputMonitor.cs` 窗口统计 (已有)
- `pet_chatter.gd` 碎碎念 (已有)
- `datalog` 数据日志 (已有)

### 工作量: 1~2 天

## 三、硬件状态联动

**目标**: 宠物和用户的设备"共生"——设备出问题，宠物也有反应。

### 具体内容

- **断网检测**: C# `NetworkInterface.GetIsNetworkAvailable()` 监听，断网时全息屏切 ERROR 模式 + 瞳孔红光闪烁 + 气泡 "信号丢失。"
- **低电量反应**: 笔记本电池低于 20% 时全息屏 BATTERY 模式自动激活 + 话术提醒
- **高负载感知**: CPU/内存压力过高时瞳孔抖动、弹性形变加强，模拟"过热"

### 依赖

- 全息屏多模式 (已有 ERROR/BATTERY/WARNING)
- `pet_effects.gd` 特效系统 (已有)
- C# 层需要新增少量系统查询方法

### 工作量: 2~3 天

## 四、番茄钟 / 专注模式

**目标**: 待办系统的自然延伸，从"记录要做什么"到"帮你去做"。

### 具体内容

- **倒计时器**: 25 分钟工作 + 5 分钟休息，全息屏实时显示进度
- **打断检测**: 结合窗口感知，专注期间切到娱乐应用时宠物提醒
- **统计报告**: 每日专注时长、被打断次数，纳入数据日志

### 依赖

- 待办系统 (已有)
- 全息屏渲染 (需新增一个倒计时模式)
- 窗口感知 (方向二)

### 工作量: 2~3 天

## 五、文件投喂系统 (进行中)

**目标**: 把文件拖到宠物身上，宠物可以对文件执行各种操作。

### 已完成

- **骨架 + 模块化架构**: `file_drop/` 目录，动作注册/分发机制，新增操作仅需添加文件+一行注册
- **操作菜单 UI**: 宠物两侧药丸按钮 (左[取消] 右[指令] → hover 展开子菜单)，跟随宠物移动
- **[粉碎] 数据销毁**: 二次确认面板 (跟随宠物) → 两种强度:
  - 回收站 (C# `SHFileOperation` + `FOF_ALLOWUNDO`，可恢复)
  - 彻底粉碎 (`File.Delete`，不可恢复)
- **C# FileOperations.cs**: `GetFileInfo()` / `DeleteFilePermanently()` / `RecycleFile()` / `OpenInExplorer()`

### 待实现的操作模块

| 操作 | 文件 | 说明 |
|------|------|------|
| [扫描] 属性检索 | `action_scan.gd` | 调用 `GetFileInfo()` → 逐条气泡显示文件名/大小/类型/日期 |
| [定位] 源路径追踪 | `action_locate.gd` | 调用 `OpenInExplorer()` → 资源管理器打开并选中 |
| [复制路径] | `action_copy_path.gd` | 文件完整路径复制到剪贴板 |
| [预览] 图片查看 | `action_preview.gd` | 图片文件在全息屏上显示缩略图 |

### 依赖

- 全息屏多模式 (已有 CLEANUP/ERROR)
- C# `FileOperations.cs` (已有)
- Godot `files_dropped` 信号 (已接入)

### 工作量: 骨架已完成，每个新操作模块约 0.5~1 天

## 六、天气同步

**目标**: 宠物和用户处在同一个"世界"里。

### 具体内容

- **天气获取**: 公共 API (和风天气/OpenWeatherMap)，启动时查询一次，之后每小时刷新
- **环境粒子**: 下雨 → 雨滴粒子，下雪 → 雪花粒子，晴天 → 柔和光晕
- **全息屏天气模式**: 新增一个渲染器显示温度、天气图标
- **话术联动**: "检测到降水概率 80%。建议携带防水装置。"

### 依赖

- `pet_effects.gd` 粒子扩展 (需新增)
- 全息屏渲染器 (需新增)
- HTTP 请求 (Godot HTTPRequest 节点)

### 工作量: 3~5 天
