## 二、实际采用的架构模式

### 2.1 委托模式（最核心的模式）

骨架持有引用，实际逻辑委托给 RefCounted 子模块。**全项目统一惯例**。

```
主控制器 (Node/CanvasLayer)
├── 子系统A (RefCounted, 通过 ctx/pet 引用主控制器)
├── 子系统B (RefCounted)
└── 子系统C (RefCounted)
```

**实例**：
- `pet.gd` → `PetHUD / EyeBehavior / PetEffects / IdleBehaviors / PetGaming / PetHoloScreen / PetMovement` 等 10 个 RefCounted
- `context_menu.gd` → `sec_pet / sec_behavior / sec_visual / sec_play / sec_system / info_sidebar / submenu_system / menu_tooltip / effect_preview` 共 9 个 RefCounted
- `game_terminal.gd` → 状态机驱动，大厅/游戏两套 UI 动态切换

**约定**：
- 子模块 `extends RefCounted`，在 `_init(parent)` 中保存主控制器引用（多用 `ctx` / `pet` / `mgr` 命名）
- 主控制器单向持有子模块引用，子模块之间**不直接互相引用**，通过主控制器或 EventBus 通信
- 子模块命名：功能分区用 `sec_<区域名>.gd`，子系统用 `<职责>.gd`（如 `submenu_system.gd`）

### 2.2 状态机模式（宠物行为核心）

```
pet.gd._init_states() 中 preload 所有状态 → Dictionary
pet.transition_to("state_name") 切换
每个状态实现 enter / exit / process / physics_process / input 五接口
```

**约定**：
- 状态文件在 `entities/pet/states/` 下，一个状态一个文件
- 状态类继承 `PetState extends RefCounted`（不是 Node）
- 新增行为 = 新建状态文件，不塞进已有状态
- 切换幂等：`transition_to` 目标与当前相同直接 return

### 2.3 游戏插件模式（游戏终端专用）

```
games/<game_id>/
    game.gd   ← extends TerminalGameBase（必须）
    icon.gd   ← extends TerminalGameIcon（必须）
    theme.gd  ← extends GameThemeOverride（可选）
```

骨架 `_scan_games()` 自动发现，新增游戏零入侵骨架。详见 `06_游戏终端开发指南.md`。

### 2.4 工厂方法（UI 组件复用）

重复创建相同结构的 UI 控件时，提取成静态工厂方法。

**实例**：
- `GameTerminalStyles.create_result_overlay()` — 所有游戏的结算覆盖层
- `ProfileStyles.*` — 装置终端所有 Tab 的共享 StyleBox/Label

### 2.5 主题代理模式（游戏终端主题系统）

```
GameTerminalStyles (静态代理)
    查询链: 游戏覆写层 > 当前终端主题 > 基类默认值
```

游戏代码只调 `GameTerminalStyles.accent()` 等，不关心底层主题切换。

## 三、通信方式

| 场景 | 方式 | 示例 |
|------|------|------|
| 跨模块广播（不知道谁在听） | EventBus 信号 | `EventBus.night_mode_changed.emit(true)` |
| 父→子或主控→子系统 | 直接调用 | `pet.holo_screen.show_idle(side, 25.0)` |
| 子系统→主控 | 通过保存的引用调用 | `ctx._make_menu_btn(...)` |
| 面板间协调（层级、穿透） | EventBus + `panel_focus_requested` | 装置终端/游戏终端点击置顶 |

**禁止**：跨模块用 `get_node("/root/...")` 直接找节点。

## 四、DWM 穿透策略（新增面板必读）

| 面板类型 | 策略 | API |
|---------|------|-----|
| 小型弹窗（右键菜单、待办面板、踏板外观） | 全窗口阻塞 | `EventBus.context_menu_toggled.emit(true/false)` |
| 大型面板（装置终端、游戏终端） | 精确区域 | `pet.set_overlay_rect("key", Rect2(...))` 每帧更新；关闭时 `pet.remove_overlay_rect("key")` |

**注意**：精确区域策略支持多面板同时打开（key 互不干扰），全窗口阻塞会覆盖精确区域效果，不要混用。

## 五、鼠标 filter 规则（CanvasLayer 低层级面板）

装置终端和游戏终端使用 `layer = -1`（宠物渲染在面板上方）。低层级的 Control 默认 `MOUSE_FILTER_STOP` 会吞掉宠物的鼠标事件。

| 控件 | mouse_filter | 原因 |
|------|-------------|------|
| 结构性容器（VBox/HBox/MarginContainer/Panel/Scroll） | `MOUSE_FILTER_PASS` | 让事件传到 `_unhandled_input` |
| 纯装饰（Label/Separator） | `MOUSE_FILTER_IGNORE` | 不参与鼠标处理 |
| 空 Control 占位（spacer） | `MOUSE_FILTER_IGNORE` | **极易遗漏**，默认是 STOP |
| 需要响应点击的按钮 | `MOUSE_FILTER_PASS` + `gui_input` 手动处理，先检查 `pet.is_mouse_on_pet()` | 宠物优先 |

骨架层（`pet_profile_panel.gd` / `game_terminal.gd`）的 `_input` 阶段会统一拦截并转发给宠物，**新增游戏不需要处理这个问题**。

## 六、瞳孔方向管理（开发约束）

`eye_behavior.forced_look_dir` **只能由 `pet.gd` 的决议层写入**，其他任何文件禁止直接赋值。

决议优先级（由高到低）：
1. `gaming.active` → 游戏态方向（全息屏方向）
2. `holo_screen.is_terminal_mode` → 终端模式方向
3. `movement.is_active` → `movement.direction`
4. 无活跃来源 → `Vector2.ZERO`（自然追踪）

需要方向时，通过 `pet.movement.start()` / `activate()` / `finish()` / `cancel()` 接口操作，不直接操作 `forced_look_dir`。

## 七、话术编写规范

话术常量用 `const _POOL_XXX` 命名，在 `TerminalGameBase` 游戏中用 `_pick()` 洗牌防重复：

```gdscript
const _POOL_WIN := ["...分析完成。", "胜负已定。", "...结果符合预期。"]
var _q_win: Array = []

func _pick(queue: Array, pool: Array) -> String:
    if queue.is_empty():
        queue.append_array(pool)
        queue.shuffle()
    return queue.pop_back()
```

话术内容遵循人设（冰山系 kuudere），具体规则见 `01_项目架构.md` 零节。

## 八、命名规范（实际惯例）

| 类型 | 命名 | 示例 |
|------|------|------|
| 文件 | `snake_case.gd` | `pet_holo_screen.gd` |
| 类名 | `PascalCase` | `class_name GameTerminalStyles` |
| 函数/变量 | `snake_case` | `var walk_speed := 100.0` |
| 私有函数 | `_snake_case` | `func _build_lobby() -> void` |
| 常量 | `UPPER_SNAKE_CASE` | `const PET_RADIUS := 30.0` |
| 信号 | 过去时态或事件名 | `signal drag_started`, `signal pet_gaming_changed` |
| 分区 builder | `sec_<名称>.gd` | `sec_pet.gd`, `sec_behavior.gd` |
| 游戏脚本 | 固定 `game.gd` / `icon.gd` / `theme.gd`（在子目录下） | `games/gomoku/game.gd` |
